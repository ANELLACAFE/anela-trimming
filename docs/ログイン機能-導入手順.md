# ログイン機能（第1段階）導入手順 ／ 実施記録

メールOTP（6桁コード）ログインで、飼い主様・わんちゃんの情報を次回から自動入力できるようにする機能です。
このドキュメントは **Supabase 側の設定手順** 兼 **実施記録** です。コード（`index.html` / `script.js` / `style.css`）はブランチに反映済みです。

> ## ✅ 実施状況（2026-08時点・すべて設定＆テスト済み）
> - **① DB＋RLS** … 実行・確認済み
> - **② SMTP（Gmail App Password 方式）** … 設定・実送信成功
> - **③ メール本文を6桁コード化** … 保存済み
> - **④ OTPを6桁・有効期限10分に調整** … 保存・再送信で6桁確認済み
> - **⑤ 動作テスト（メール到達）** … 受信トレイ着（迷惑メール入りなし）
>
> **残タスク**：フロント（ログインUI）は現在このブランチのみ。**本番（GitHub Pages / main）へ反映すると、お客様が実際に使えるようになります。** 反映前に、実機で「メール→コード入力→自動入力」の一連フローを一度通すのがおすすめ。

> ## ⚠️ 重要な順序の注意（実際にハマった点）
> Supabase は **「カスタムSMTPを有効にしないと、メール本文テンプレートを編集できない」** 仕様です。
> そのため **必ず ②SMTP → ③テンプレート の順**で行います（先にテンプレを触ろうとしても編集ロックされます）。

## ① データベースの用意（SQLを実行）

1. Supabase ダッシュボード → 左メニュー **SQL Editor** → **New query**
2. リポジトリ内の [`supabase/login_setup.sql`](../supabase/login_setup.sql) の中身を全部コピーして貼り付け → **Run**
   - `drop policy ...` を含むため「破壊的操作」警告が出るが、ポリシーを貼り直すだけなので **Run query** で続行してよい（データは消えない）

作られるもの：
- `profiles`（飼い主様情報）／`pets`（わんちゃん情報）テーブル
- **RLS（行レベルセキュリティ）** … 本人の情報しか読み書きできない（プライバシー保護の要）
- `reservations.user_id` 列（ログイン中の予約を紐づけ。既存の匿名予約は影響なし）
- `reservations` に「本人の予約だけ読める」select＋ログイン中insertのポリシー（第2段階マイページの仕込み）

## ② 外部メール送信（Gmail App Password 方式）★先にこれ

Supabase 標準メールは1時間2通・迷惑メール入りしやすいテスト用。**Gmailの純正SMTP**を使うと、DNS設定なしで確実に届きます（無料・1日約500通で用途に十分）。

### 事前準備（お店のGoogleアカウントで）
送信元にする **anellacafe.minamiurawa@gmail.com** で：
1. **2段階認証をON**（`https://myaccount.google.com/signinoptions/two-step-verification`）
   - ONにしないと次の「アプリパスワード」が使えない
2. **アプリパスワードを発行**（`https://myaccount.google.com/apppasswords`）
   - 名前は任意（例：Supabase yoyaku mail）→ 表示される **16桁**を控える（普段のGmailパスワードとは別物。ここ専用の鍵）

### Supabase側の入力
**Authentication → Emails → SMTP Settings** で **Enable custom SMTP** をON、以下を入力して保存：

| 項目 | 値 |
|---|---|
| Sender email | anellacafe.minamiurawa@gmail.com |
| Sender name | ANELLA CAFE 南浦和店 |
| Host | smtp.gmail.com |
| Port | 465 |
| Username | anellacafe.minamiurawa@gmail.com |
| Password | 発行した**16桁のアプリパスワード**（スペースなし） |

> 「個人向けSMTPなので配信に影響の可能性」という警告は出るが、少量のログインコード用途では問題なし。
> ⚠️ Chromeの自動入力で誤ったパスワードが入ることがある。パスワード欄は一度クリアしてから16桁を貼ること。
> もし送信できない時は Port を 465→587 に変えて試す。

## ③ メールに「6桁コード」を表示する設定

②でカスタムSMTPをONにすると、テンプレート編集が解禁される。

1. **Authentication → Emails → Templates** → **Magic link or OTP** を開く
2. **Subject** を分かりやすく：`【ANELLA CAFE】ご予約ログインの確認コード`
3. **Body（ソース）** を丸ごと下記に置き換え（`{{ .Token }}` が6桁コードになる）→ 保存

```html
<h2>ANELLA CAFE ご予約ログイン</h2>
<p>下記の確認コードを、予約ページの入力欄にご入力ください。</p>
<p style="font-size:28px; letter-spacing:6px; font-weight:bold;">{{ .Token }}</p>
<p>このコードの有効期限は約10分です。心当たりがない場合は、このメールを破棄してください。</p>
```

---

## ④ OTPの桁数・有効期限を合わせる ★フロントと桁数を一致させる

**Authentication → Sign In / Providers → Email** を開き、下の方の2項目：

- **メールOTPの長さ** … **6**（デフォルトが8になっていることがある。フォームは6桁前提なので必ず6に）
- **メールOTPの有効期限** … **600**（秒＝10分。テンプレ文言と一致・セキュリティ的にも短めが安全）

保存して完了。

> ⚠️ ここを6以外にすると、フォーム側（`script.js` の6桁検証／入力欄 maxlength=6）と食い違い、正しいコードでもログインできなくなる。桁数を変える時は必ずフロントも合わせること。

## ⑤ 動作テスト

- **メール到達テスト（実施済み）**：予約ページ、または直接APIで自分宛にOTP送信 → 受信トレイに6桁コードが届けばSMTP＋テンプレートOK。
- **一連フローのテスト（本番反映前におすすめ）**：
  1. 予約ページを開く（キャッシュが残る場合はスーパーリロード）
  2. 上部「ログイン（かんたん・任意）」で自分のメール → **確認コードを送る**
  3. 届いた6桁を入力して **ログイン**
  4. 初回：フォームを入力して予約 → 完了
  5. 再訪問し再ログイン → **飼い主・わんちゃん情報が自動で入っていれば成功** 🎉
- **RLS確認**：別メールでもう1アカウント作り、そのアカウントでは他人の情報が一切出ないことを確認（＝RLSが効いている証明）

## 困ったときは

- **コードが届かない** → 迷惑メール確認。②のGmail SMTPが有効か、アプリパスワードが正しいか
- **「6桁ではなくリンクが届く」** → ③の `{{ .Token }}` 置き換えができているか
- **「コードが8桁で来る／正しいコードなのに弾かれる」** → ④で **OTPの長さ=6** になっているか
- **ログイン予約だけ失敗する** → ①のSQL（特に `reservations.user_id` 列とinsertポリシー）が実行済みか
- **自動入力されない** → 一度ログアウト→再ログイン。別アカウントで他人の情報が出ないのは正常（RLS）
